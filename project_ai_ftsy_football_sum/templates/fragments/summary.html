The summary is Markdown, and is shown as prose with its source underneath — the same gesture as "show me the underlying error" on a failure. Both come from the server: `summary_html` is rendered by `services/markdown.py` on the saved run's page and carried on a live run's terminal event, and nothing in the browser ever builds markup. Three containers rather than one, because a live run is watched before it is read: the streamed text is what arrives word by word, and the prose and the source are what it becomes. `run.js` swaps between them when the run ends; a saved run arrives with the swap already done. #} {% import "macros.html" as macros %} {# Hidden only when there is nothing to show *and* nothing to act on: a live run before its first word.
